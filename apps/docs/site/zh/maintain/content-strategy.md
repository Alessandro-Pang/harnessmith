# 内容与双语策略

本文规定 Harnessmith 文档如何分层、如何判断事实、如何维护中英文内容，以及什么时候需要同步测试。它既是维护约定，也是读者遇到冲突时的判断依据。

## 文档分层

| 层级 | 负责回答的问题 | 内容边界 |
| --- | --- | --- |
| README | 这是什么？适合我吗？如何开始？ | 定位、适用人群、宿主、安装、最短路径、安全摘要和导航 |
| 指南 | 我该怎样完成一件事？ | 场景化步骤、前置条件、结果、故障和恢复 |
| 概念 | 为什么这样设计？边界在哪里？ | 架构、设计取舍、责任归属、状态和证据模型 |
| 参考 | 命令或字段究竟怎么写？ | 完整参数、退出码、配置、迁移和机器可读事实 |
| 维护 | 贡献者如何改、测和发布？ | 内容规范、构建门禁、owner、双语和发布流程 |
| 代码、schema、测试 | 当前实现到底做什么？ | 可执行契约、默认值、拒绝条件和回归证据 |

发生冲突时，先核对当前代码、schema、测试和 manifest，再修正文档；文档不能提升代码没有提供的保证。测试可以锁定关键事实，但不能代替人对阅读顺序和解释质量的判断。

## 每页的标准结构

公开页面默认采用下面的顺序，主题特殊时可以增删章节，但要让读者先得到结论，再进入细节：

1. **用途与范围**：说明目标读者、要解决的问题和不能证明的内容；
2. **最短路径**：给出可以直接复制的命令或步骤；
3. **结果与判断**：说明成功输出、状态含义和下一步；
4. **解释与边界**：解释设计原因、宿主依赖、限制和 `inconclusive` 条件；
5. **相关入口**：链接到更深的指南、参考页、源码或证据。

命令旁边写清是否只读、是否写入、所需权限和失败后的恢复动作。代码示例应能独立运行，路径使用占位符而不是作者机器上的绝对路径。

## README 精简门禁

README 只承载第一次阅读必需的信息，但“精简”不等于删掉读者做决定所需的事实。删除一段内容前，确认它是重复、过时或纯实现细节；仍会影响安装、宿主选择、安全判断或维护决策的内容必须迁移到对应指南或参考页，并附上迁移清单，同时同步导航和测试。

README 中保留：项目定位、适用人群、核心能力、宿主列表、最短安装路径、常用恢复命令、安全边界、文档入口和当前限制。完整参数、内部实现和评测协议放在站点中。

## 双语规则

中文是深度技术内容的 canonical 版本。中文和英文 README 必须保持相同的信息架构、核心能力、宿主列表、命令和安全边界。英文站点至少提供英文定位和快速开始；未完成翻译的深度页面应明确链接到中文 canonical 页面，不复制一份无人维护的旧译文。

修改以下事实时必须同时检查中英文入口：

- 安装命令、默认宿主和退出码；
- `installed`、`healthy`、`host-configured`、`host-verified` 等状态；
- 宿主支持、scope、路径和权限边界；
- `implemented`、`delegated`、`unsupported`、`inconclusive` 的定义。

导航语言应与页面语言一致。英文页面可以链接到中文深度页，但应在链接文字中明确说明“Chinese technical docs”。

## Owner 与同步触发器

frontmatter 的 `owner` 表示维护责任，`audience` 表示主要读者，`status` 表示页面是否仍是公开入口。以下变化需要回查文档：

- CLI 命令、参数、默认值和退出码；
- Adapter、宿主 scope、路径和环境变量；
- schema、状态机、迁移和安全边界；
- 发布、评测和 capability evidence；
- `public/` 静态资源、站点 base 和导航。

PR 中应指出事实源、受影响页面和验证命令；不要只写“同步文档”。

## 手写、生成与发布边界

Markdown、导航和页面解释由维护者编写。VitePress 生成 HTML、搜索索引、sitemap 和资源，但生成物不是事实源。`apps/docs/site/capability-evidence.yaml` 是机器可读的能力清单；公开页面链接到仓库中的 canonical 文件，避免维护一份没有一致性门禁的副本。若未来需要把 YAML 作为站点下载资源发布，必须同时增加源文件与发布副本的一致性检查。

构建阶段生成本地搜索索引，供站内关键词检索使用；它不提供向量语义召回，也不改变文档事实源。搜索结果只能帮助定位页面，不能替代代码、schema 和测试核对。

仓库根目录 `docs/` 用于 ADR、内部提案和工作稿，不自动进入公开站点。内部文档可以记录候选方案，但必须在公开页面中明确哪些已经实现、哪些仍是计划。

## 搜索与版本边界

站点使用 VitePress 本地搜索。索引与页面同一次构建生成，不依赖外部搜索服务，也不会把搜索词发送到服务器。当前方案不提供向量语义召回。文档规模变大后，本地索引和自然语言召回会有边界；在升级搜索方案前，先记录规模、加载时间和召回问题，再比较分词、模糊匹配或语义检索。

每页的 `updated` 只说明内容最近一次调整，不代表代码版本永远兼容。涉及版本差异时写明版本或日期，并以当前代码、schema 和测试重新核对。
