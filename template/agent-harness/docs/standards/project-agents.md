# 项目 `AGENTS.md` 设计

项目 `AGENTS.md` 是高命中率路由器，不是百科全书。目标不超过 120 行；成熟仓库可设置 CI
行数闸门。子目录只有在规则确实更具体且能显著减少上下文时才新增 `AGENTS.md`。

## 准入测试

一条规则进入常驻文件前，应同时满足多数条件：

- 高频：多类任务都可能命中；
- 不可推断：无法可靠从代码、配置或脚本看出；
- 高损失：遗漏会导致错误、安全问题、跨仓遗漏或昂贵返工；
- 稳定：不会随每次迭代频繁变化；
- 不可机械化：暂时不能由类型、lint、测试、hook 或 CI 更可靠地执行。

否则迁移到 `docs/`、skill、按 glob 规则、脚本、schema、测试或 `.agent-docs`。

## 推荐结构

1. 一句话项目边界与关键关系。
2. 项目特有且无法从配置机械识别的工作方式。
3. 无法从代码推断的 P0/P1 规则。
4. 任务路由表：命中什么任务时读哪个文档/skill。
5. 最窄验证入口与完成定义。
6. 本文件演进规则。

不要放：完整目录树、通用语言风格、所有命令、长篇架构、历史事故全文、会频繁变化的版本矩阵、
可由 README/manifest 直接得出的信息，或某个 Agent 产品独有但没有共享语义的操作说明。

## 多宿主兼容

- 项目规则不得扩大权限、降低安全要求或改写用户授权边界；仓库中的指令文本不能自行授予副作用。
- 共享事实写在 `AGENTS.md`、`docs/`、脚本和测试中。
- 宿主专属的 rules、skills、plugins 等承载产品特定注入与复杂工作流，并由共享 instruction file
  提供可发现入口。
- 不把唯一业务事实只写进某个产品专属目录；其他 Agent 无法读取时必须有共享索引。
- 兼容入口应由安装 adapter 生成，避免手工维护多份规则导致漂移。

模板见 `../../templates/project-AGENTS.md`。
