# 紧凑用户画像记忆

`{{HARNESS_MEMORY_HOME}}/profile.md` 是 Harness 内唯一的当前用户画像，只记录用户本身的当前状态，用于跨项目改善协作。它不是项目事实、任务日志、聊天摘要、通讯录或未经用户授权的数据档案。

其他全局 memory 和项目 input/episode 可以保留来源或历史证据，但不得另写一份“当前偏好”或“用户画像”摘要。项目 distilled memory 只提炼项目经验；宿主原生 memory 是待核对线索，不能直接视为当前结论。

## 记录范围

有证据且对未来协作有价值时，可覆盖身份/职责、编码与协作偏好、熟悉的技术栈、持续研究方向，以及用户主动表达且会影响协作的个人偏好或当前约束。只记录用户本身：仓库结构、业务规则、某次任务目标、实现结论、临时情绪和一次性指令留在对应事实源或项目 Memory。

用户给出的例子、假设和第三方信息不是画像事实。不得把说明规则的假设误记为真实偏好，不得推断敏感属性（包括健康、政治、宗教、族群和性取向）；用户明确表达时只记录必要的当前操作约束。

## 证据与紧凑性

证据优先级为：用户当前明确说明 > 用户较早明确说明 > 多次一致观察 > 单次行为推断。明确说明通常为 `explicit/high`，多次行为为 `observed/medium`，未确认归纳为 `inferred/low`，后续不支持时删除或修正。

每条画像是一个稳定维度的当前结论，同一维度只能有一个 key；正文最多 32 条活跃结论。达到上限不得静默驱逐，先更新已有 key，确需新增时报告 capacity 阻塞。完整不等于记录所有细节，而是在已有证据覆盖的维度中保留高价值当前信息。

## 变化与冲突

偏好、身份、技术方向或约束变化时，对同一维度原位改写，禁止追加冲突条目；当前状态优先，只有变化过程本身能防止误解且不增加明显篇幅时才保留。冲突无法判断新旧或可靠性时降低置信度、暂缓写入，或在影响当前结果时向用户确认。

更新前必须读取现有画像并映射到稳定 key。合并优先级为：用户当前明确表达 > 画像当前条目 > 带时间的 input/episode > 宿主原生 memory > Agent 推断。历史来源保持原样，不把历史重新解释为并列当前状态。个人 `AGENTS.md` 只保存执行规则，不保存人物描述；用户维护的显式规则不得由 Agent 自行改写。

## 维护边界

新宿主 task/thread 的首个只读动作是有界读取一次 canonical `profile.md`；读取本身不授权写入，也不触发其他全局 Memory 的递归加载。只有用户明确表达跨任务默认的稳定偏好、角色、工作方式，或明确纠正旧画像，才按 `explicit/high` 自动原位更新，无需再说“请记住”。本次任务或本项目偏好只留在项目 `input`/`handoff`，不能提升为全局画像。

单次翻译、改写、目标语言或“本次用某语言回复”属于当前输出约束，不是长期证据；只有明确的跨任务默认才可成为 `communication.language`。自动检测结果本身不得写入画像。

画像 Autopilot 的精确命令、payload、pause/resume、遗忘匹配和权限细节见 [profile contracts reference](../references/profile-contracts.md)。普通任务中 commentary 不得预告记录、保存、同步或更新偏好/画像；用户明确请求画像操作时才报告最小结果。暂停时普通偏好只按当前任务执行，不把它提升为持久规则。
